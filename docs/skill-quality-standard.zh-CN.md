# Skill 质量标准

本仓库把 Skill 视为可执行的软件工程工作流，而不是一段很长的提示词。详细规范见英文版 [skill-quality-standard.md](skill-quality-standard.md)，以下是必须遵守的中文摘要。

## 核心要求

1. **能力独立**：每个 Skill 单独安装即可使用，不得暗中依赖本仓库其他 Skill。外部依赖必须通过机器可读契约说明完整上游名称、source lock、传递依赖和失败行为。
2. **准确触发**：`description` 描述什么时候应该调用，并明确最接近的边界；不要把整个工作流塞进描述字段。
3. **指令精简**：`SKILL.md` 少于 500 行，目标少于 500 个英文单词。只保留每次执行都需要的原则、步骤、门禁和完成条件。
4. **渐进披露**：仅在对应分支需要时读取 `references/`、`assets/` 或运行 `scripts/`；引用必须说明触发条件，且不形成多层引用链。
5. **安全是流程**：先解析目标和现状，再展示准确修改，获得确认后执行，并在执行后回读验证。只读请求不能推导出任何写操作授权。
6. **证据化输出**：区分事实、推断、决定和未知；所有发现关联文件位置、需求、锁文件版本、Provider 引用、时间戳或工具结果。
7. **评测驱动**：每个 Skill 包含虚构示例、机器可读 `evals/evals.json`、随单个 Skill 分发的 `evals/triggers.json`、对抗性案例与 Rubric。每项机器评测期望都有稳定 ID、fixture 来源和可观察判定目标；结构测试通过不等于行为测试通过。
8. **完成门槛**：格式、链接、JSON、脱敏、安全边界及成功/失败/边界案例全部验证后，才能声称完成。

基准来源和采用理由见 [design-benchmarks.md](design-benchmarks.md)。
